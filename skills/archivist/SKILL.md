---
name: archivist
description: Manual conservative cleanup of bead-linked Codex or Claude Code conversations.
---

Use [entry](../shared/entry.md). For authorized cleanup, get candidates from `bin/hive telemetry links --json` in the configured Hive `repository` (`hive` may not be on PATH; it needs `python3.12` or `HIVE_PYTHON`). Deduplicate IDs and restrict cleanup to the configured project and current host. Use the link's discovered `host` and native host records, not UUID version, to distinguish Codex from Claude; leave the other host's sessions for its own archivist run and skip unresolved host identity. User-supplied threads may be added explicitly. Native task lists may establish activity and existing archive membership, but titles and the full conversation index do not expand default membership. Skip already archived tasks.

Links are observation membership, not current ownership: `executor` includes historical assignees and survives release, reassignment and closure. Read current native Beads assignments with `bd list --all --limit 0 --assignee <candidate-id> --json` and inspect relevant beads with `bd show`, using the [routing prefix](../shared/routing.md). Skip a candidate only for ownership when its current `assignee` equals that candidate and its status is not `closed`, including a currently assigned deferred bead. Creator links, former assignments and unassigned deferred beads do not block archiving. Do not change bead status or ownership to manufacture eligibility; uncertain native ownership means skip that candidate.

Require native inactivity and at least 15 minutes since the latest input, output or tool activity. In Codex, `idle` with a completed, failed or interrupted latest turn is sufficient inactive evidence; do not demand a separate queue-empty field the app does not expose. `notLoaded` alone is insufficient: corroborate it with a terminal latest turn and an old native activity timestamp. Explicit running tools, queued input or a newer turn override an idle summary. A closed bead or completed title alone proves nothing. Never interrupt or stop a turn to make it eligible.

Use the native archive operation's actual scope: inspect child tasks when it also archives them, using native relationships and complete relevant pages. A child task is a subagent session, not a child bead. Do not assume every archive cascades or demand an unrelated global descendant inventory for a single-task archive. If affected children or their activity cannot be established, skip that candidate and report the specific missing evidence; continue checking other candidates.

Immediately before each archive, recheck current ownership and activity for the target and any affected children. Recheck native activity afterward and promptly unarchive any newly archived target/children if a turn raced the operation, preserving tasks that were already archived. Compare turn/input/output/tool evidence, not a timestamp advanced solely by archiving. Report archived, already archived, currently owned and genuinely uncertain candidates separately; inactivity is not evidence of an erroneous stop.

In the Claude desktop app, use `get_session`, `archive_session` and `unarchive_session`. They address sessions by app ID (`local_...`), not the `CLAUDE_CODE_SESSION_ID` stored on beads. Archive only when the user or a native record establishes that mapping; otherwise skip. The app's session record, `~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json`, holds `sessionId` and the bead-side `cliSessionId`; it is undocumented app state, so skip when it is absent or lacks either field. `isRunning=false` and `lastActivityAt` supply inactivity evidence; explicitly pending input or tool activity overrides them, but a missing separate queue field alone does not block cleanup. Archiving also archives finished side sessions sharing the worktree. Find descendants with `get_session`, which reports `parentSessionId`, on every unarchived session from `list_sessions`; its default `limit` is 20, so raise it until the list is complete, or treat affected descendants as unknown. The app may refuse pinned or on-screen sessions; report the refusal rather than retrying. Each archive asks for approval except in auto mode, which may approve silently, and bypass permissions mode. Plain Claude Code CLI sessions have no archive tool.
