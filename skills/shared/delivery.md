# Native delivery

Claim before substantive work; follow-up work after a close gets a new bead rather than a reopen. After an acknowledged native claim, create a Tollgate worktree with `tg worktree create NAME --json`. Implement within scope, run `scripts/check-fast` and focused checks, then commit with a Conventional Commit message. Apply the [executor review policy](../executor/SKILL.md) to decide whether to schedule review. When required, request a fresh cold 🛡️ warden subagent with no inherited conversation (a Codex subagent, or a Claude Code Agent-tool subagent told to use the warden skill). Give it scope, diff/base/source, workspace, invariants and checks. Address substantive findings and review source-changing fixes within that review.

Submit with `tg candidate HEAD --json`, approve with `tg approve ID --wait --json` and inspect/wait with `tg status ID --json` or `tg wait ID --json`. Run waits from a durable project directory; promotion may remove a clean worktree. Settle workspace-rooted background writers first. Keep the bead assigned through review, CI, provider draining and uncertain outcomes. A cancelled observation client does not prove provider work stopped.

Confirm the exact candidate, tested integration result, promotion and configured local/remote synchronization. A dirty local master can lag remote completion, so inspect native candidate and actual local-master inclusion until Tollgate's native interface proves this distinction. Only then record completed outcome and close the bead. Handle in-scope CI/conflict failures on the same bead; unknown delivery remains assigned for investigation.
